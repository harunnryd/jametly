## [Unreleased]

### Added
- **Invisible hotkey overlay and typed bridge client** (`JAM-0014-overlay-frontend`): first usable frontend. New `app/src/lib/bridge.ts` collapses the three sidecar stream namespaces (`chat.*`, `ask.*`, and the bare `debug.stream` kinds) onto one `StreamEvent` union discriminated by `kind`, validating every payload with `zod` and dropping malformed events rather than rendering partial state. The task's AC named a `chat_stream_chunk` Rust event; no such event exists — `lib.rs` forwards the sidecar's `event.method` verbatim, so the real frontend surface is `listen("stream.event")`, and the client maps that instead (no IPC schema change, no new Rust event). `Reply` is `#[serde(untagged)]` on the wire, so the client narrows on the presence of `result`/`error` rather than a discriminant, and classifies `jamly_invoke`'s bare-string rejections into `ENGINE_STOPPED` (the only signal the UI gets to offer `jamly_restart_engine`) versus `TRANSPORT`. Because events are lossy by design (256-deep bounded channel, drop-newest), the **reply** is treated as the authoritative terminal signal — a dropped `chat.done` still settles the UI. `startChat` always sends an explicit `thread_id`, since `chat.cancel` targets threads and an auto-generated id is invisible to the caller until the reply lands. New `app/src/App.tsx` + `hooks/useChatStream.ts` + `components/` render the 600x54 overlay: a labeled text input (not `role="combobox"` — ARIA 1.2 requires a combobox to own a popup, and there are no suggestions until JAM-0021), a `role="log"` answer region with implicit `aria-atomic="false"` so assistive tech announces only appended tokens, `aria-busy` flipped across the stream, and a separate `role="status"` for lifecycle. Escape cancels an in-flight stream and dismisses the overlay when idle. Rust-side, new `src-tauri/src/window.rs` (pure `overlay_origin` geometry — horizontally centred, top-anchored, clamped onto short/narrow monitors, recomputed per show with a `current_monitor` → `primary_monitor` fallback) and `src-tauri/src/shortcuts.rs` (accelerator parsing, media-key rejection, Wayland detection). The hotkey is registered in **Rust**, not JS: it needs no `global-shortcut:*` ACL entries and works before the webview loads. `CmdOrCtrl+Shift+Space` is bound via `tauri-plugin-global-shortcut`, filtered to `ShortcutState::Pressed` so the toggle fires once per press, unregistered before re-register, and released on `ExitRequested`. Media keys are rejected by name because they route through `CGEventTap` on macOS and fail silently without Input Monitoring — ordinary combos use Carbon `RegisterEventHotKey` and need no TCC grant, so jametly prompts for no new macOS permission. Wayland has no global-shortcut protocol and tao disables the thread outright, so an unsupported session reports honestly instead of appearing broken. `CloseRequested` now hides instead of closing, and macOS uses `ActivationPolicy::Accessory` (`skipTaskbar` is a no-op there). Adds the previously-missing `src-tauri/capabilities/default.json` — without any capability file the ACL denies **every** `invoke`, so no frontend could have talked to the sidecar at all — and `src-tauri/entitlements.plist`, which `bundle.macOS.entitlements` already referenced but did not exist, failing macOS bundle builds. `tauri.conf.json` gains `visible: false` (the window config had `focus: false`, which controls initial focus only and does not hide anything), `alwaysOnTop`, and non-closable/minimizable/maximizable, plus a real `devUrl`/`beforeDevCommand` and a `frontendDist` that points at Vite's actual output. Vitest is wired into Tier 0 `verify` and `js-typecheck` into `verify-ci`, and CI gains the Node/pnpm setup it never had. The macOS non-activating `NSPanel` (Tauri cannot produce one; `focusable: false` is broken on macOS per tauri#14102) is deliberately left to JAM-0017, which owns OS-specific window APIs — the overlay therefore still activates the app on macOS when focused. Packaged-app E2E is **not** included: `tauri-driver` has no macOS support, and the only cross-platform path embeds an HTTP WebDriver server in the shipping binary, which needs `@security-owner` review against ADR-0006 before it goes near a product that markets itself as fully local.
- **Sidecar crash detection and bounded restart supervision** (`JAM-0025-sidecar-supervision`): new `src-tauri/src/supervisor.rs` with a pure `RestartPolicy` (exponential backoff from 500 ms capped at 30 s, a 5-restart burst over a sliding 60 s window, and a 10 s `healthy_after` uptime that resets both), `Death`/`classify` exit classification (clean vs exit code vs signal, `#[cfg(unix)]`-gated), a byte- and line-bounded `StderrTail`, and the `Supervisor` state machine that emits the already-documented `python.crash` (`{traceback, exit_code, signal}`) and `python.restarted` (`{reason, pid}`) events. `src-tauri/src/bridge.rs` gains an injectable `SidecarCommand` spawn seam, `Stdio::piped()` stderr so a traceback is capturable at all, `Sidecar::send` split from `request` so no caller awaits a reply while holding the sidecar lock, and `await_exit`, which joins the stdout reader *before* reaping the child so buffered replies are delivered instead of discarded — the previous `Drop` impl aborted the reader, which would turn a clean shutdown into a spurious failure. Pending requests are failed exactly once by draining the waiter map under a single lock acquisition and sending after release; each failure carries a typed `INTERNAL` reply naming the death, and requests after give-up fail fast with `EngineStopped` rather than hanging. Nothing is replayed across a restart (at-most-once): a crash after a side effect but before its reply is indistinguishable from a crash before it. `lib.rs` moves the event channel up to the supervisor so it survives restarts (the old per-child sender left the UI deaf after the first crash) and forwards lifecycle events to the frontend via `tauri::Emitter`, plus a `jamly_restart_engine` command for the manual reset out of the terminal give-up state. Python-side, `serve` now returns a deterministic exit code (`0` clean, `130` signalled), handles `SIGTERM`/`SIGINT` by draining in-flight work before exit, and announces `pid` and interpreter version on stderr; `run` drives its own loop so a signal cannot hang on joining the blocked stdin reader thread. No IPC schema change (both event `method`s were already documented and the v1 envelope leaves `method` free-form), no new dependency, no `ErrorCode` variant added.
- **Meeting summaries, grounded action items, and follow-up classification** (`JAM-0012-followups-and-summaries`): new `ai/src/jamly/meetings/extractor.py` (`EvidencedItem` / `ActionItem` / `ActionItems` / `FollowUp` / `FollowUps` / `FollowUpOutcome` pydantic models, full-transcript loading with a char budget, ID-tagged transcript rendering, `evidence_property` grammar fragments, `bind_structured` + `structured_call` bounded repair loop, `ground_items` grounding filter, `stamp_followups`, `followup_event`, `extract_followups`) and `ai/src/jamly/meetings/summarizer.py` (`SummaryPoint` / `MeetingSummary` / `SummaryOutcome`, `summary_schema`, `summarize_transcript`, `summarize_meeting`). `ai/src/jamly/meetings/__init__.py` gains `run_post_process` + `PostProcessResult`, which summarizes a finished meeting, extracts follow-ups, and emits one `followup.emit` event per grounded follow-up with `{meeting_id, kind, body, ts_ms, citations}`. Structured output uses `with_structured_output(schema, method="json_schema", include_raw=True)` so decoding is grammar-constrained on Ollama, and every `source_utterance_ids` field is an `enum` closed over the transcript's real IDs plus the `UNKNOWN` sentinel (up to `MAX_ENUM_IDS`), making hallucinated citations unrepresentable; `ground_items` is kept as defence in depth and drops any entry citing a missing utterance or `UNKNOWN`, recording a reason line rather than failing the run. Validation failures feed the error back into the prompt for at most `MAX_REPAIR_ATTEMPTS` attempts; an exhausted budget, a schema mismatch, or a dead provider degrades to an empty summary with a reported error instead of raising, so a failed extraction never loses the meeting. Follow-up `ts_ms` is derived from the earliest cited utterance rather than generated by the model. Summaries are returned as typed data and not persisted: the `checkpoints` row keyed by `meeting_id` is already taken by `SessionsPayload` (ask sessions) and `CheckpointPayload` (orphan recovery), and `LocalStore.save_checkpoint` requires the key to be a real meeting id, so writing summaries there would clobber ask history. Persisting and rendering them is the export layer's job (`JAM-0016`). No IPC schema change (`followup.emit` is an already-documented event `method`, and the v1 envelope leaves `method` free-form with open `params`), no schema migration, no new runtime dep.
- **Ask graph with bounded transcript context, citations, observable tool calls, and per-meeting checkpoints** (`JAM-0011-ask-graph`): new `ai/src/jamly/agent/state.py` (`Citation` + `AskState` pydantic models), `ai/src/jamly/agent/ask.py` (`ask.stream` / `ask.cancel` handlers, bounded rolling transcript context built tail-first within a char budget, citation emission per in-scope utterance, tool-path dispatch for read-only tools, `PYTHON_TIMEOUT` via `asyncio.wait_for`, canonical provider error mapping), `ai/src/jamly/agent/tools.py` (`ToolSpec` registry + read-only `search_history` tool with a `mutates` gate; mutating tools are rejected by ask handlers), and `ai/src/jamly/agent/checkpoint.py` (`load_ask_state` / `save_ask_state` against the existing `checkpoints` table; one row per meeting holding a multi-session payload, recovers after restart). `ask.stream` emits ordered `stream.event` kinds `ask.state` / `ask.token` / `ask.citation` / `ask.tool_call` / `ask.tool_result` / `ask.done` / `ask.error` with the request id as `correlation_id` and a caller-supplied or auto-generated `thread_id`. `ask.cancel` uses the existing `TaskRegistry.cancel_thread` index for in-flight cancellation; `TaskRegistry.cancel_thread` now takes `exclude_request_id` so a cancel handler does not cancel its own siblings, and `handle_chat_cancel` passes the same kwarg (latent bug fixed). The bridge auto-wires `ask.stream` + `ask.cancel` when both `store` and `config` are provided. No IPC schema change, no new runtime dep.
- **Local LLM provider factory + streaming chat** (`JAM-0010-provider-factory`): new `ai/src/jamly/llm/` package (registry, `ProviderInfo`, `ProviderKind`, `ChatMessage`, `build_chat_model` against the built-in `ollama` AI + `faster-whisper` STT providers) and `ai/src/jamly/agent/chat.py` with `chat.stream` / `chat.cancel` / `providers.list` / `providers.set_selected` handlers. `chat.stream` emits ordered `stream.event` kinds `chat.token` / `chat.state` / `chat.done` / `chat.error` with the request id as `correlation_id` and a caller-supplied or auto-generated `thread_id`. `chat.cancel` uses the existing `TaskRegistry.cancel_thread` index for in-flight cancellation; the bridge's `CancelledError` path surfaces a `cancelled=true` reply + `stream.event kind=cancelled` so events remain lossy. `providers.list` returns configured AI/STT providers with `default_model` + `kind`; `providers.set_selected` persists to `~/.config/jametly/config.toml` via new `load_config` / `save_config` (stdlib `tomllib` + hand-rolled writer, no new dep). `PYTHON_TIMEOUT` via `asyncio.wait_for(deadline_s)`; `ProviderAuthError` / `ProviderRateLimitError` / `ProviderUnavailableError` / `ProviderMalformedResponseError` map to `PROVIDER_AUTH` / `PROVIDER_RATE_LIMIT` / `PROVIDER_UNAVAILABLE` / `PARSE_ERROR`. Tests use the new `FakeChatModel` (no network). No IPC schema change, no new runtime dep.
- **Meeting session lifecycle** (`JAM-0009-meeting-session`): new `ai/src/jamly/meetings/session.py` with `meeting.start` / `meeting.stop` / `meeting.list` / `meeting.get` IPC handlers. Idempotent start rejects duplicate active sessions with `INVALID_REQUEST`. Stop flushes pending work, closes the session via a conditional `UPDATE meetings SET ended_at = CURRENT_TIMESTAMP WHERE id = ? AND ended_at IS NULL`, and emits `meeting.ended` exactly once (the rowcount gate is the linearization point). List/get return stable bounded results with FTS5 search. Cold-start recovery writes a `checkpoints(thread_id=meeting_id)` row with `status="recovered_on_cold_start"` for every meeting whose `ended_at IS NULL` and does not close them; the user/dashboard decides the recovery UX. No new dependencies, no schema migration, no IPC schema change.
- **Local STT pipeline** (`JAM-0008-stt-pipeline`): Python-owned speech-to-text pipeline with a lazy `faster-whisper` CTranslate2 adapter, a ring-buffered silero-VAD gate that turns a 30 ms ingest cadence into the exact 512-sample frames silero accepts, cumulative partials plus one final event per voiced segment, deterministic offline-friendly tests against a fake provider, and typed-error mapping for bad inputs, unavailable models, and slow inference. Remote speech-to-text providers remain approval-gated in JAM-0020 and speaker diarization in JAM-0019.
- **SQLite meeting store** (`JAM-0007-sqlite-store`): Python-owned standard-library SQLite schema with versioned migrations, meetings/utterances/messages/action items, FTS5 search, bounded results, transaction rollback, and no telemetry tables. Vector search and the Rust read-cache remain approval-gated in JAM-0031/JAM-0032.
- **Secure config contract** (`JAM-0006-secure-config`): Rust-owned provider-secret namespace, non-disclosing typed errors, deterministic in-memory secret store, and strict Python configuration defaults under `~/.config/jametly/`. Native OS keychains and atomic TOML persistence remain approval-gated in JAM-0029 and JAM-0030.
- **Screen capture abstraction** (`JAM-0005-screen-capture`): standalone Rust capture contract with overflow-safe region validation, deterministic RGBA mock capture, sanitized permission/unavailable errors, confined PNG blob output, and stale-blob cleanup. Native xcap monitor capture remains approval-gated in JAM-0028.
- **Audio backend abstraction** (`JAM-0004-audio-backend`): standalone Rust audio contract with 16 kHz mono PCM frames, monotonic timestamps, bounded drop-newest frame delivery, deterministic mock capture, lifecycle/device-loss errors, and chunking property tests. Native microphone/loopback drivers remain approval-gated in JAM-0027.
- **Async sidecar runtime** (`JAM-0003-async-sidecar-runtime`): new `ai/src/jamly/bridge.py` running an asyncio runtime — one task per request, so a slow handler blocks neither unrelated requests nor event delivery. Adds `OutboundStream` (single lock-serialized stdout writer, no interleaved NDJSON), `TaskRegistry` (in-flight tasks keyed by request `id`, with a `thread_id` index for the future `chat.cancel`), a new `stream.event` kind `cancelled`, and the `debug.sleep` transport diagnostic. Cancellation resolves both the terminal event and the correlated reply, since events are lossy by design. Stdin is read off the event loop so a blocking pipe read cannot stall in-flight handlers. `__main__.py`'s synchronous `REGISTRY`/`_handle`/`_serve` remain for wire compatibility.
- **Full-duplex IPC spine** (`JAM-0002-ipc-events`): additive `Event` envelope in `shared/schemas/ipc/v1.json` with serde (`ipc_proto::{Event, WireMessage}`) and Pydantic (`jamly.protocol.Event`) mirrors; the Rust bridge now reads sidecar stdout on a background task, correlates replies by id, and surfaces fire-and-forget events through a bounded channel (`EVENT_CHANNEL_CAPACITY = 256`, drop-newest overflow policy with a dropped-event counter). Python gains a method registry and the `debug.stream` transport diagnostic; `Reply` rejects envelopes carrying both `result` and `error`. Contract tests add an `insta` envelope snapshot and `proptest` invariants.
- **Phase 0 skeleton bridge** (`JAM-0001-stdio-bridge`): `core/ipc-proto` (serde envelope types), `ai/src/jamly` (Python sidecar with `echo` + error envelopes), `src-tauri` (Tauri shell + `bridge::Sidecar` via `tokio::process::Command`). Rust bridge/protocol tests, Python unit tests, and subprocess integration tests pass with 100% `ipc-proto` line coverage and 91.89% Python coverage. Verified manually: echo, unknown-method, malformed-JSON paths all produce canonical wire output.
